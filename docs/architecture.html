CrewAI Multi-Agent Stock Analyser

Complete architecture, code flow & functional reference — generated 5 March 2026

🗺️ System Overview

The application is a full-stack, real-time stock analysis system that orchestrates three specialised AI agents via CrewAI, running local LLMs through Ollama. Each analysis session is streamed live to the browser over a WebSocket, and the final result is rendered as a downloadable PDF report.

🚀 Python main.py – FastAPI Application

backend/main.py

The entry-point. Defines REST endpoints, a ConnectionManager for WebSocket sessions, and wires incoming WS messages to StockAnalysisCrew.

ConnectionManager

Maintains a dictionary { session_id → WebSocket }. Each analysis run gets a UUID-based session ID. The manager's send() method serialises a Python dict to JSON and writes it to the correct socket.

REST Endpoints

MethodPathDescription
GET /api/health Liveness probe – returns {"status":"ok"}
GET /api/models?base_url=… Queries Ollama /api/tags and returns available model names. Falls back to a static list if Ollama is unreachable.
GET /api/report/{session_id} Streams the generated PDF as application/pdf. Returns 404 if PDF not yet created.

WebSocket Endpoint – /ws/{session_id}

The primary communication channel. On connection:

  1. 1
    Accept and register manager.connect(ws, session_id) stores the socket.
  2. 2
    Receive JSON message Reads { symbol, llm_model, ollama_base_url } from the client.
  3. 3
    Create crew & run Instantiates StockAnalysisCrew with a send_update callback, then calls await crew.run().
  4. 4
    Cleanup on disconnect Handles WebSocketDisconnect gracefully.

🎛️ Python crew.py – Pipeline Orchestration

backend/crew.py

The most architecturally important file. StockAnalysisCrew bridges the synchronous CrewAI execution model with async FastAPI/WebSocket.

The Thread-Bridge Pattern

CrewAI's crew.kickoff() is a blocking synchronous call. It cannot yield control back to the asyncio event loop. The bridge works as follows:

# crew.py – simplified
# 1. CrewAI runs in a thread-pool executor (non-blocking)
future = loop.run_in_executor(None, self._run_crew_sync)

# 2. Async loop polls an in-process Queue every 150 ms
while not future.done():
    await self._drain_queue()    # send buffered events via WebSocket
    await asyncio.sleep(0.15)

# 3. Final drain after crew finishes
await self._drain_queue()

Event Queue

CrewAI callbacks (_step_callback, _task_callback) run on the thread-pool thread and write dicts into a queue.Queue. The async event loop drains this queue and forwards events over WebSocket. This is thread-safe because queue.Queue is designed for producer/consumer across threads.

Callback Hooks

CallbackTriggerEmits Event
_step_callback(step_output) After every agent reasoning step or tool call tool_use or thinking
_task_callback(task_output) After each of the 3 tasks completes task_complete then agent_start (for next agent)

PDF Generation (post-crew)

After the crew finishes, the orchestrator:

  1. Calls _fetch_stock_info(symbol) — hits the 5-minute TTL cache populated by Agent 1, so no extra network request is made.
  2. Calls generate_pdf_report(report_text, symbol, session_id, stock_data=…).
  3. Emits a crew_complete event with the PDF download URL.

Agent 3
agents/report_writer.py

Role: Senior Investment Strategist & Report Writer

Max Iterations: 6 (no tools — writing only)

Tools: None

Synthesises Agent 1 and Agent 2 outputs into an 800–1200 word institutional-grade report with BUY/HOLD/SELL recommendation, price targets, bull/bear case, and risk factors.

max_iter behaviour Each iteration is one think → act → observe loop. If an agent has not produced a Final Answer by its max_iter limit, CrewAI forces a graceful exit using the best partial output available. Agent 3 gets fewer iterations (6) because it has no tools to call.

📋 Python Tasks

Tasks define what an agent must do and what its output should look like. Each task is a crewai.Task with a description, expected_output, and an assigned agent.

Task 1 — Fundamental & Technical Analysis

tasks/analysis_tasks.py

Instructs Agent 1 to call both tools and produce a report with three labelled sections: Fundamental Analysis, Technical Analysis, and Preliminary Assessment with scores 1–10.

Task 2 — News Research & Sentiment

tasks/news_tasks.py

Instructs Agent 2 to fetch and summarise the top 8–10 news stories, corporate events, analyst activity, macro context, and provide a News Sentiment Score 1–10.

Task 3 — Investment Report Generation

tasks/report_tasks.py

Uses context=[analysis_task, news_task] so Agent 3 automatically receives the outputs of both previous tasks. Instructs the writing of an 8-section report (Executive Summary → Company Overview → Fundamental → Technical → News → Recommendation → Risks → Conclusion) with a clear BUY/HOLD/SELL verdict and price target ranges.

🔧 Python Tools

stock_tools.py

backend/tools/stock_tools.py

StockDataTool – "Get Stock Fundamental Data"

Calls _get_info(symbol) → yf.Ticker.info with fast_info fallback for price fields. Returns JSON with 30+ fundamental metrics.

TechnicalAnalysisTool – "Get Technical Analysis Indicators"

Calls _get_history(symbol, "6mo") → yf.download() primary (less rate-limited), ticker.history() fallback. Feeds the OHLCV DataFrame to the ta library and computes:

  • RSI (14), MACD (12/26/9), Bollinger Bands (20/2σ)
  • Stochastic Oscillator (%K, %D), ATR (14)
  • SMA-20, SMA-50, SMA-200, EMA-20
  • 1W / 1M / 3M / 6M / YTD return percentages
  • Volume vs 20-day average ratio

news_tools.py

backend/tools/news_tools.py

StockNewsTool – "Get Stock News"

Routing logic based on the exchange suffix:

Symbol typeSourceFallback
*.NS / *.BO (Indian) 🇮🇳 Zerodha Pulse — scrapes pulse.zerodha.com DuckDuckGo News with Indian context keywords
All other symbols 🌐 DuckDuckGo News — ddgs.news(query, max_results=12) —

The Zerodha Pulse scraper uses _NSE_ALIASES (a dict of 50+ tickers → common headline names) to match articles even when the full company name appears in text (e.g. COALINDIA → "Coal India").

MarketSentimentTool – "Get Market Sentiment"

Uses DuckDuckGo ddgs.text() with two queries. For .NS/.BO stocks the queries use Indian market context ("NSE analyst rating", "Moneycontrol", "Economic Times", "NDTV Profit"). Also retrieves yfinance analyst consensus (target mean/high/low, recommendation key, number of analyst opinions).

🔌 React useWebSocket.js

frontend/src/hooks/useWebSocket.js

Custom hook encapsulating WebSocket lifecycle management.

  • connect() — creates a new WebSocket to ${WS_BASE}/ws/${sessionId}, wires onopen, onclose, onerror, onmessage.
  • disconnect() — closes the socket and nulls the ref.
  • send(data) — serialises to JSON and sends only if socket is in OPEN state.
  • readyState — reflects current WebSocket.CONNECTING / OPEN / CLOSED.

Uses a useRef stable reference to the onMessage callback to avoid stale-closure issues during re-renders.

🔄 End-to-End Request Flow

  1. 1
    User enters ticker (e.g. RELIANCE.NS) and clicks Analyse App.js generates a UUID session ID, opens WebSocket to ws://localhost:8000/ws/{sessionId}.
  2. 2
    WebSocket accepted (main.py) ConnectionManager stores the socket. Client sends { symbol: "RELIANCE.NS", llm_model, ollama_base_url }.
  3. 3
    StockAnalysisCrew.run() awaited (crew.py) Emits started event. Launches _run_crew_sync in asyncio.run_in_executor.
  4. 4
    Agent 1 – Stock Analyst (stock_analyst.py / analysis_tasks.py) LLM decides to call StockDataTool → yfinance ticker.info fetched and cached. LLM decides to call TechnicalAnalysisTool → yf.download() + ta indicators. Produces structured text output. Each step emits tool_use / thinking events via queue.
  5. 5
    Task 1 complete → Agent 2 – News Researcher (news_researcher.py / news_tasks.py) task_callback emits task_complete + agent_start. For RELIANCE.NS: StockNewsTool calls _fetch_zerodha_pulse_news("RELIANCE.NS") — scrapes Pulse, filters by alias "Reliance". MarketSentimentTool calls DuckDuckGo with Indian-context queries.
  6. 6
    Task 2 complete → Agent 3 – Investment Strategist (report_writer.py / report_tasks.py) Receives Agent 1 and Agent 2 outputs as context. Writes 8-section report with BUY/HOLD/SELL recommendation. No tool calls — pure LLM generation.
  7. 7
    Crew finishes → PDF generation (pdf_generator.py) _fetch_stock_info returns cached info (zero network cost). generate_pdf_report() builds ReportLab PDF with cover, metrics banner, recommendation badge, 8 sections. Saves to reports/{sessionId}_report.pdf.
  8. 8
    crew_complete event sent Browser receives { type: "crew_complete", pdf_url: "/api/report/{sessionId}" }. ReportViewer renders the download button. User clicks → browser calls GET /api/report/{sessionId} → PDF file streamed.

🗃️ Caching Strategy

A module-level, in-process TTL cache in stock_tools.py prevents redundant network calls within the same analysis session.

Cache keyContentTTLWho reads it
info:{SYMBOL} Full ticker.info dict (30+ fields) 5 min Agent 1 (StockDataTool), crew.py (PDF metrics)
hist:{SYMBOL}:{period} OHLCV pd.DataFrame 5 min Agent 1 (TechnicalAnalysisTool)
Zero extra network cost for PDF By the time PDF generation runs, the info:{SYMBOL} cache is already warm from Agent 1's earlier call. crew.py calls _fetch_stock_info(symbol) which returns the cached dict instantly — no HTTP request is made.

Zerodha Pulse Scraper Details

  • Strips .NS/.BO/-EQ suffix to get base ticker.
  • Looks up _NSE_ALIASES dict (50+ tickers → common headline names) e.g. HINDUNILVR → ["HUL", "Hindustan Unilever"].
  • Fetches the Pulse homepage with browser-like headers. On macOS SSL certificate chain error, retries with verify=False.
  • Parses HTML with BeautifulSoup4; targets #news-list li.item with fallback to <h2> elements.
  • Extracts: title, date (e.g. "3.5 hours ago"), source outlet, summary, URL.
  • Returns up to 12 matching articles (configurable via max_results).

⚠️ Error Handling & Rate-Limit Strategy

yfinance 429 Rate Limiting

Root cause: yfinance 0.2.x had a broken cookie/crumb layer causing frequent 429 Too Many Requests from Yahoo Finance endpoints.

Fix: Upgraded to yfinance ≥1.0.0 (resolves to 1.2.0) which has a completely rewritten HTTP layer with automatic 429 recovery.

Additional mitigations in stock_tools.py:

  • _jitter_sleep(lo, hi) — random 1–3s sleep before each outbound call
  • yf.download() instead of ticker.history() — hits a less rate-limited endpoint for OHLCV data
  • 5-minute TTL cache — at most one fetch per ticker per 5 minutes
  • ticker.fast_info fallback — lightweight endpoint when full ticker.info is empty

Zerodha Pulse SSL Error (macOS)

macOS Python installations sometimes fail to verify Zerodha's certificate chain. The scraper catches requests.exceptions.SSLError and automatically retries with verify=False.

Agent Graceful Exit

If an agent exceeds its max_iter limit, CrewAI stops the iteration loop and returns the best partial output. The task callback still fires, so downstream agents receive whatever context was produced — the pipeline does not crash.

WebSocket Disconnect

main.py catches WebSocketDisconnect and calls manager.disconnect(session_id). Subsequent sends from the crew (still running in the thread pool) are silently dropped in ConnectionManager.send().
